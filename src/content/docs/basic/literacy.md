前端开发不缺教程，缺的是找到好资料、读懂它，再动手解决问题的能力。这一章先讲几件值得尽早养成的习惯：读英文文档、用好搜索、主动验证，以及把问题说清楚。

## 良好的英语阅读能力

**建议尽早习惯直接阅读英文技术文档。** 规范、更新说明、报错和开源项目讨论经常首先以英文发布。每次都等别人翻译、整理成中文教程，学习和排查问题就多了一道障碍。

不用等英语「学好了」才开始。技术文档反复使用的词汇比较集中，先从自己正在用的 API 和错误信息读起，结合示例理解，比背一堆脱离场景的单词更容易坚持。推荐这样练习：

1. 搜索技术问题时先用英文 API 名、错误原文和关键词，直接阅读找到的英文资料。
2. 官方没有中文文档时，直接读英文原文，别先花半天寻找第三方翻译。用翻译工具辅助理解，参数名、否定词、版本要求和限制条件要回到原文核对。
3. 阅读正在使用的库的源码和 issue，熟悉命名、注释与讨论问题的表达方式。

有维护良好的官方中文文档就放心用；遇到翻译含糊、内容过时或查不到的细节，再回到原文。目标是能自己拿到答案。

- [专为程序员编写的英语学习指南](https://github.com/yujiangshui/An-English-Guide-for-Programmers)
- [freeCodeCamp 学习课程](https://www.freecodecamp.org/learn)

## 主动学习及好奇心

围绕实际问题理解技术的用途、代价和适用边界。看到有趣的功能，可以查阅文档、构造最小示例或阅读源码验证自己的猜想；不必把追逐新框架当作学习进度。

为实验记录环境、输入和结果。无法复现的经验结论，尤其是性能和兼容性结论，应保留条件而不是直接推广到所有项目。

## 使用搜索引擎的能力

遇到问题，优先找官方文档、项目 issue 和能复现问题的讨论。搜索引擎负责帮你找到它们；排名靠前、点赞多，或者生成式回答写得很肯定，都不能代替验证。

### 能访问 Google

**查技术问题，本书优先推荐 [Google](https://www.google.com/)，配合英文关键词使用。** 直接搜索 API 名、完整报错和项目名，找到官方文档、GitHub issue 或相关技术讨论后再深入阅读。

Google 无法访问时，用 [Bing](https://www.bing.com/) 作为备选，或直接去 MDN、框架官网和 GitHub 仓库查。已经知道项目叫什么，就先找官网，别在一堆转载教程里兜圈子。

### 会用 Google

以下技巧也适用于其他搜索引擎，但具体运算符支持需要看各自说明。

#### 使用恰当的关键词

1. 把业务背景与技术问题分开，例如“微信活动页文字垂直居中”通常先检索 `CSS vertical alignment`。
2. 添加必要环境：框架主版本、运行时、浏览器、错误代码等。
3. 优先阅读完整错误和调用栈，搜索时去掉个人路径、令牌与不相关数据。
4. 检查结果的发布时间与适用版本，用最小示例验证方案。

#### 使用英文关键词

中文结果不足时，可尝试英文 API 名和错误原文。反过来也可以借助中文教程理解概念，再回到规范或官方文档核对细节。

#### 使用高级搜索指令

使用引号搜索词组，或用 `site:` 限定官方站点，例如 `site:developer.mozilla.org fetch response.ok`。排除词等指令并不保证结果与某个主题完全无关。

参考 [Google 搜索帮助](https://support.google.com/websearch/answer/2466433?hl=zh-Hans)。

### 关于百度等国产搜索引擎

**不推荐用百度搜索技术问题，也不建议把它设为日常开发的默认搜索引擎。** 原因很直接：广告和推广入口干扰检索，内容农场、复制粘贴的教程和过时答案增加筛选成本，搜索国外工具时还得费力辨认哪个才是官网。初学者最容易被看似完整、实际错误的答案带偏。

具体要避开的坑有这些：

- **广告、下载站冒充官方入口。** 搜索开发工具是为了安装工具，结果先绕进下载器、培训广告和推广页，甚至遇到虚假宣传或诈骗信息，纯属浪费时间。
- **转载层层套娃。** 一段代码被原样复制到多个站点，看起来很多人都这样写，实际可能是同一个错误被抄了很多遍。
- **旧答案包装成新教程。** 不交代版本，示例已经失效，照着操作只会多出一串新问题。
- **内容农场挤占结果。** 大段关键词、重复解释和「解决方案大全」读完一圈，连问题为什么发生都没讲清楚。

本书的建议是直接换工具：Google 优先，Bing 备选，官方文档和项目 issue 优先于转载站。遇到 CSDN 等技术社区的文章，重点看是否解释原因、注明版本、给出可验证的代码；只贴一段「亲测有效」的命令，又找不到出处的，直接跳过。

**珍爱生命，远离百度。** 把时间花在读懂问题和写代码上，别耗在辨认广告、洗稿和错误答案上。

## 如何提问

遇到困难时，可以向同事或社区求助。能独立完成的查阅和尝试有助于缩小问题，但无法准确命名问题的初学者也可以说明目标与卡住的位置。

提问时尽量提供：

1. 想达到的目标、实际结果与预期结果。
2. 能复现问题的最小代码、操作步骤和必要的环境版本。
3. 原始错误信息，以及已经尝试过的方案和结果。
4. 与问题有关的背景，避免只询问自己猜测的解决方案。

共享代码和日志前移除凭据、个人资料和无关数据。参考[如何创建最小可复现示例](https://stackoverflow.com/help/minimal-reproducible-example)。

## 良好的学习能力

面对新技术，可以依次问：它解决什么问题、有哪些限制、目标平台是否支持、如何验证效果、维护和迁移成本如何？

用自己的话解释原理，并通过一个小项目验证理解。把结论与适用条件一起记录，之后遇到不同版本或环境时重新核对。
