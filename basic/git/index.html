Git 的安装及使用

每个可说明的小改动做一次提交，推送前看 diff。 Git 在本地保存历史，GitHub、GitLab 等托管平台负责交换与协作；本地提交不会自动备份到远程。

基本概念

Section titled “基本概念”
  • 工作区：当前正在编辑的文件。
  • 暂存区：准备包含在下次提交中的内容。
  • 提交：记录文件快照及其历史关系。
  • 分支：可随新提交移动的引用；标签常用于标记版本。
  • 远程仓库：用于交换提交的其他仓库，本地提交不会自动上传。

参考 Pro Git 简体中文译本。

Mac

Section titled “Mac”

默认用 Homebrew 运行 brew install git，再用 git --version 检查。已经通过系统命令行工具安装也可以继续用，重点确认终端实际执行的是哪一个版本。

Windows & Linux

Section titled “Windows & Linux”

按本书推荐的 WSL 开发方式，在 Ubuntu 里运行 sudo apt-get install git，代码和 Git 操作都留在 WSL。必须用原生 Windows 工作流时再装 Git for Windows。安装后用 git --version 确认，别让两个环境交替改同一份依赖目录。

GUI 程序安装

Section titled “GUI 程序安装”

图形客户端本书推荐 Sourcetree。把提交历史、分支和文件差异放在图形界面里看，对理解 Git 很有帮助，也方便在提交前认真检查自己改了什么。

已经习惯 VS Code 内置的源代码管理界面，也可以继续用；其他选择有 Fork 和 Windows 上的 TortoiseGit。先把提交、分支和合并的含义弄清楚，别把折腾客户端当成学习 Git。

GUI 与命令行都应遵循团队约定，不必统一强制创建合并提交。

分支问题

Section titled “分支问题”

小项目默认用 main + 短期功能分支 + PR。 合并后继续从更新过的 main 开新分支，别为一个人维护的练习项目先搭五层长期分支。加入已有团队则遵守它的发布流程；默认分支叫什么，以仓库实际配置为准。

一次提交尽量对应一个清晰改动，先检查暂存内容再提交。不要把密钥、个人配置或生成依赖目录混入提交；.gitignore 不会自动移除已经跟踪的文件。

撤销与同步

Section titled “撤销与同步”
  • 只取消暂存可用 git restore --staged 文件名，它保留工作区改动。
  • git restore 文件名 会丢弃对应的未暂存改动，执行前应确认差异。
  • 已共享的提交需要撤销时，通常优先使用 git revert 提交号 生成反向提交。
  • reset --hard、清理未跟踪文件和强制推送都可能导致内容丢失，理解影响并遵循团队流程后再使用。

远程认证按平台说明选择 HTTPS 凭据或 SSH；GitHub 的 HTTPS Git 操作不使用账户密码。参考 GitHub 认证说明。

代码提交日志

Section titled “代码提交日志”

约定式提交是一种可选的协作规范，不是 Git 的语法要求。团队采用时应统一配置与含义。

结构

Section titled “结构”

例如 feat(search): support keyboard navigation。冒号后跟一个空格，正文和脚注按规范分隔。

类型说明

Section titled “类型说明”

规范定义 feat 表示功能、fix 表示修复，并允许团队使用其他类型，例如 docs、test、build、ci、perf、refactor 和 chore。常用配置中的 style 通常指格式调整；修复页面样式缺陷仍可使用 fix，不应仅因修改 CSS 就归为 style。

破坏性变更

Section titled “破坏性变更”

在类型或作用域后添加 !，或者在脚注中使用 BREAKING CHANGE: 描述，都可以标记破坏性变更；两者可同时使用，但规范没有要求必须同时写。BREAKING CHANGE 不限于正文的第一行。

基于 Git 提供源码托管的服务

Section titled “基于 Git 提供源码托管的服务”

个人项目和开源项目，本书优先推荐 GitHub。把代码、README、issue 和 PR 放在一起维护，便于别人了解、使用和参与你的项目；认真维护一个可运行、有说明、有提交记录的项目，也比只列一串「熟悉某某技术」更能展示你的能力。

团队已经使用 GitLab、Bitbucket 等平台，就先按团队流程协作。需要自建托管或特定部署能力时再比较方案，选择套餐前核对当前功能与额度。

继续阅读 GitHub CI/CD与 GitLab CI/CD。
